# 架构说明 · Architecture

> 本文描述 TabPilot 的模块划分、数据流与关键算法。
> 阅读顺序建议：`目录职责` → `两种模式的差异` → `跟随算法` → `桌面壳（Tauri）`。

---

## 1. 整体分层

```text
┌─────────────────────────────────────────────────────────────┐
│ 前端（public/，纯 Web，零框架）                              │
│   index.html        谱面模式入口                             │
│   image-tab.html    图片谱模式入口                           │
│   css/              设计令牌 → 布局 → 控件（三层样式）        │
│   js/theme.js       主题早期注入（防闪烁）                    │
│   js/settings.js    设置持久化 + 设置抽屉                     │
│   js/app.js         谱面模式业务（渲染、跟随、放大镜）        │
│   js/image-tab.js   图片谱业务（校准、时间轴、放大镜）        │
│   sw.js             PWA 离线缓存                             │
├─────────────────────────────────────────────────────────────┤
│ 桌面 / 移动壳（src-tauri/，Rust + 系统 WebView）             │
│   tauri.conf.json   窗口、打包、版本、图标配置                │
│   build.rs          生成上下文 + Windows 版本资源(rc)         │
│   src/main.rs       程序入口                                 │
│   src/lib.rs        应用构建与启动                            │
│   capabilities/     权限声明（仅 core:default）               │
└─────────────────────────────────────────────────────────────┘
```

设计原则：**前端不依赖任何桌面专有 API**。`public/` 整个目录可以脱离 Tauri
直接部署为静态站点（PWA），因此同一套代码既能出桌面端、也能出移动端和网页版。
麦克风所需的「安全上下文」由 Tauri 的资产协议天然满足，无需额外处理。

## 2. 两种模式的差异

| | 谱面模式（`index.html`） | 图片谱模式（`image-tab.html`） |
|---|---|---|
| 输入 | Guitar Pro / MusicXML / MIDI / alphaTex | JPG / PNG 截图 |
| 位置信息 | 乐谱模型自带 tick / 小节 | **无**，需先校准谱行 |
| 校准 | 不需要 | 投影识别谱行 + 检测小节线，或手动框行 |
| 时间轴 | 依乐谱 tempo 精确展开 | BPM × 每行小节数近似展开 |
| 跟随方式 | BPM 滚动 / 麦克风 / 模拟 | 匀速推进 + 节拍器 |
| 放大镜 | 克隆 SVG 矢量放大 | Canvas 光栅放大 |

**坐标约定（图片谱）**：`bands` 中的 `y0/y1/x0/x1` 一律使用**图片原始像素**。
显示缩放由 `#imgWrap` 的 CSS zoom 统一处理，覆盖层是其子元素，会自动跟随，
因此业务代码永远不需要感知当前缩放比例。

## 3. 跟随算法（OTW-lite）

谱面模式的麦克风跟随位于 `js/app.js`，核心是「色度向量对齐」：

1. **构建参考轨道**：乐谱载入后为每一拍计算 12 维 chroma（音级分布，忽略八度），
   同时标注 `_tick`、`_timeMs`、`_mbIndex`、`_domId`（用于高亮 DOM 定位）。
2. **实时取帧**：`AnalyserNode`（fftSize 8192）取频谱，只保留 **75–1400 Hz**
   （吉他基频范围）且高于噪声门的频段，累加成 12 维向量并归一化。
3. **窗口匹配**：在当前位置 `[-6, +12]` 拍的窗口内取余弦相似度最大值，
   减去 `0.025 × 距离` 作为位置先验惩罚。
4. **迟滞 + 防抖**：新位置需「明显更优」或「当前相似度过低」才切换，
   且连续两帧确认后才生效，避免在相似和弦间反复横跳。
5. **失联重定位**：连续 8 帧相似度低于 0.5 时，改为全曲搜索最佳匹配
   （应对中途跳段演奏）。

置信度条显示的是相似度的指数平滑值；输入电平表显示有效频段峰值相对噪声门的余量。

## 4. 主题与设置

- **主题**：`css/base.css` 用 CSS 自定义属性定义两套令牌（浅 / 深），
  通过 `<html data-theme="...">` 切换。`js/theme.js` 在 `<head>` 内**同步**执行，
  在首屏渲染前就定好主题，避免深色用户看到白屏闪烁。
- **设置**：`js/settings.js` 是设置的唯一读写入口，数据存在
  `localStorage['tabpilot.settings.v1']`。页面通过 `onChange` 订阅变更，
  设置抽屉由该模块动态创建，两个模式共用，保证行为一致。
- **注意**：谱面区域底色 `--paper` 在深色主题下仍保持纸白——alphaTab 绘制的
  是深色墨迹，若跟随深色背景会失去对比度。

## 5. 桌面壳（Tauri 2）

- 相比此前的 Electron 版本，体积从 **188 MB 降到约 5 MB**：Tauri 使用系统
  WebView（Windows 上即 WebView2 / Chromium），不再打包整个浏览器运行时。
- 原 Electron 版的 `app://` 自定义协议与 GPU 回退 hack 已全部移除，
  由 Tauri 资产协议接管。
- 权限遵循最小化原则：`capabilities/default.json` 只声明 `core:default`，
  麦克风由系统 WebView 在运行时向用户申请，不做静默授权。
